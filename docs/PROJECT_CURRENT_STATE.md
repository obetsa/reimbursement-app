# Reimbursement App — Поточний стан
> Станом на 01.04.2026

---

## Що це за проект

Персональний веб-застосунок для відстеження витрат та відшкодувань. Розроблений для особистого використання як веб-версія з подальшим переходом на нативний iOS застосунок.

### Два основних сценарії

1. **Приватні платежі** — відстеження оплат із власної кишені, що мають бути відшкодовані компанією (часткові повернення, статуси, хронологія)
2. **Корпоративна картка** — облік витрат з корпоративного рахунку для звітності (без відстеження повернень)

## База даних (SQLite)

Локальна SQLite база, керована через Flask API.

**Основні таблиці:**
- `users` — облікові записи
- `records` — записи витрат
- `companies` — компанії (Betsa GmbH, PILLAR GmbH, BauPay, VL Solutions та ін.)
- `payment_instruments` — платіжні інструменти (Private Visa, Private Mastercard, Betsa card, Pillar card, Cash)
- `return_events` — події повернення коштів
- `attachments` — вкладені документи/чеки

## Реалізований функціонал

### Записи витрат
- Створення, редагування, видалення записів
- Поля: дата, сума, валюта, компанія, платіжний інструмент, опис, статус
- Деталізований перегляд із хронологією повернень
- Архівування та видалення у кошик

### Дашборд
- Загальна сума витрат та повернень
- Аналітика по статусах

### Перегляд
- Перемикання між табличним та картковим виглядом
- Фільтрація та сортування

### Вкладення
- Завантаження документів (чеки, інвойси) до записів

### Статусна логіка
Автоматичний розрахунок на основі сум:
- `no-return` — повернення не очікується / не відстежується
- `pending` — очікується повернення
- `partial` — часткове повернення
- `returned` — повністю повернено

### Налаштування
- Управління компаніями та платіжними інструментами
- Управління обліковими записами

### UI/UX
- Темна тема
- 6 кольорових палітр + 7 акцентних кольорів
- Мультимовність: 🇺🇦 українська (за замовчуванням), 🇩🇪 німецька, 🇬🇧 англійська
- Адаптований під мобільний вигляд

## Відомі баги (виявлені на момент документування)

| Баг | Опис |
|---|---|
| Дашборд | Сума не оновлюється після додавання запису |
| Редагування | Поля "Компанія" і "Платіжний інструмент" втрачають значення |
| Статус | Завжди зберігається як `no-return` |
| Архів/кошик | Не працюють |
| Налаштування | Відсутні кнопки деактивації |
| Вкладення | Немає фідбеку після завантаження файлу |

## Архітектурна історія

| Етап | Рішення | Причина зміни |
|---|---|---|
| v1 | Supabase (PostgreSQL) + Supabase Auth | Ненадійний free tier — проект засинає після 7 днів без активності |
| v2 (поточний) | SQLite + Flask (повністю локально) | Стабільність, незалежність від зовнішніх сервісів |

> **Важливо:** Supabase Storage **відхилено** на користь Google Drive для зберігання файлів у майбутньому.
